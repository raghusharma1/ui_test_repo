# Running this Appium test suite

This folder is a **self-contained [uv](https://docs.astral.sh/uv/) project**. Once a
device and an Appium server are reachable, you can run the tests directly from
here — no need to re-run the generator.

> Auto-generated by the mobile test pipeline. `pytest.ini`, `conftest.py`,
> `utils/`, and `pages/base_page.py` are framework scaffold (overwritten on every
> regeneration). Your page objects, `data/*.json`, and `tests/` are yours to edit.

---

## Prerequisites

1. **`uv` installed** and on your PATH — https://docs.astral.sh/uv/
2. **A device or emulator running** and visible to ADB:
   ```bash
   adb devices          # must list one device in the "device" state
   ```
   - **Local emulator:** e.g. `emulator-5554`.
   - **Remote / AWS emulator:** connect over TCP first, then use `host:port` as the
     device name:
     ```bash
     adb connect <ip>:<port>     # e.g. adb connect 10.0.0.5:5555
     ```
     (The suite also runs `adb connect` for you when `MOBILE_DEVICE_NAME` is a
     `host:port` value, but connecting once yourself confirms reachability.)
3. **An Appium 2.x server running** with the UiAutomator2 driver:
   ```bash
   appium driver install uiautomator2   # one-time
   appium                               # serves http://127.0.0.1:4723
   ```
4. **The app under test available.** Before the session starts the suite installs
   `MOBILE_APP_PATH` on the device via ADB automatically (see
   [App installation](#app-installation)). So either:
   - the app is already installed on the device (leave `MOBILE_APP_PATH` unset), **or**
   - set `MOBILE_APP_PATH` to the APK so the suite installs it.

## Steps

From **this directory** (the one containing `pytest.ini`):

```bash
# 1. Create your runtime .env from the template and fill in the values
cp .env.template .env

# 2. Sync dependencies into a local .venv (from pyproject.toml)
uv sync

# 3. Run the whole suite — discovers tests/, writes reports/report.html
uv run pytest

# ...or run a single feature / file
uv run pytest tests/<feature>/test_<name>.py -v --tb=short
```

Always run from the suite root (this folder), **not** from `tests/<feature>/`: the
`.venv`, `.env`, `pytest.ini`, and the `reports/` + `recordings/` output dirs all
live here, and `utils`/`pages` are importable only from here.

`uv run` auto-syncs, so step 2 is optional — but running it once surfaces any
dependency problems cleanly.

## Configure `.env`

`.env.template` lists every variable the suite reads. The important ones:

| Variable | Meaning | Example |
|----------|---------|---------|
| `APPIUM_SERVER_URL` | Appium server URL | `http://127.0.0.1:4723` |
| `MOBILE_PLATFORM` | Platform | `Android` |
| `MOBILE_APP_PACKAGE` | App package under test | `com.example.app` |
| `MOBILE_DEVICE_NAME` | ADB serial (local) or `host:port` (remote) | `emulator-5554` / `10.0.0.5:5555` |
| `MOBILE_APP_PATH` | APK to install if the app is missing | `C:\path\to\app-debug.apk` |
| `MOBILE_APP_ACTIVITY` | Launch activity — **optional**, Appium resolves it from the package | *(leave blank)* |
| `MOBILE_RESET_APP` | Clear app data before the run | `true` |
| `MOBILE_USERNAME` / `MOBILE_PASSWORD` / `MOBILE_OTP` | Credentials — only if the flow logs in | |
| `MOBILE_SKIP_APP_INSTALL` | Skip the auto app-install check | `false` |

`.env` holds real credentials — it is git-ignored; never commit it.

## App installation

App installation happens in one place — `utils/driver_factory.py::ensure_app_installed()`,
which `conftest.py` calls **once, right after the Appium session starts** (so the
standard, non-gated `is_app_installed` check is available). There is no separate
pre-session ADB step. The path taken depends on the setup:

1. **App already on the device** (a device-farm image or a previous run) — the
   install is skipped entirely and the app is just launched. You'll see
   `App <package> already exists on device — skipping install.` This is the
   common case and needs no security-gated Appium features.
2. **Local Appium server** — the server can read the APK directly, so Appium
   installs and launches it itself from the `app` capability during session
   creation. `ensure_app_installed()` is a no-op here.
3. **Remote Appium server, app genuinely absent** — the APK is installed with
   host-side `adb install` (the same way the generator installs it during agent
   exploration): the device is registered with `adb connect` when
   `MOBILE_DEVICE_NAME` is a `host:port`, then `adb install -r -g` runs. This
   needs an `adb` binary on this machine (system `adb`, or the bundled `adbutils`
   fallback) and adb reachability to the device — but **no** security-gated
   Appium features. Only if local adb can't reach the device does the suite fall
   back to uploading + installing via `mobile: shell`, which then requires the
   Appium server to be started with `--relaxed-security` /
   `--allow-insecure=adb_shell`.

`MOBILE_SKIP_APP_INSTALL=true` and an unset `MOBILE_APP_PATH` both mean "the app
is already on the device" — no local APK is registered, so installation is
skipped and the app is launched via `MOBILE_APP_PACKAGE` / `MOBILE_APP_ACTIVITY`.
`MOBILE_RESET_APP` is still honored on the skip-install path (app data is cleared
before launch).

## Where results go

- `reports/report.html` — self-contained pytest-html report for the run.
- `reports/<test>_<timestamp>.png` — screenshot captured **at the failure moment**.
- `reports/<test>_<timestamp>_hierarchy.xml` — UI hierarchy at failure.
- `recordings/test_recording.mp4` — screen recording of the session.

## Troubleshooting

| Symptom | Likely cause / fix |
|---------|--------------------|
| `A new session could not be created` / `SessionNotCreatedException` | Appium server not running, or wrong `APPIUM_SERVER_URL`. Check `curl <APPIUM_SERVER_URL>/status`. |
| App not found / test lands on the launcher | App not installed and `MOBILE_APP_PATH` unset or wrong. Set it to the APK path. |
| `adb: device not found` for a `host:port` device | Run `adb connect <host:port>` and confirm with `adb devices`. |
| `UiAutomation not connected` | A stale UiAutomator2 instrumentation holds the device. `adb shell am force-stop io.appium.uiautomator2.server` and `io.appium.uiautomator2.server.test`, then retry. |
| `Failed to install the app ...` | Local `adb` couldn't reach the device **and** the `mobile: shell` fallback is disabled. Make the device reachable from this host (`adb connect <host:port>` then `adb devices`), pre-install the app on the device (the suite then detects it and skips install), or start the Appium server with `--relaxed-security` / `--allow-insecure=adb_shell`. |
